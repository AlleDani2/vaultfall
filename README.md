# VAULTFALL

An **idle RPG / tycoon with a menu-driven interface**, built with **Godot 4.7.2** (standard edition, GDScript).
Skills and crafting, class-based combat, a crate system that is opened only with in-game currency and keys,
an estate (tycoon) layer and a multi-layer, endlessly repeatable prestige. Single-player and offline, with an
optional LAN/VPN co-op. Texts are bilingual (Italian and English).

This repository is the **source code, tools and design documents** of the game, released under the MIT licence.
It is **not a complete, playable copy**: the art, the audio and the final game data are not in it (see
[What is not included](#what-is-not-included-and-why)).

## Status

- The game itself (version 1.0.0 in `game/version.json`) is feature-complete in the private development tree:
  skills, combat and classes, crates, estate, prestige layers, eras, trials, seasonal events, optional co-op.
- This public repository is a **clean snapshot of the code, the tooling and the design documents**, published
  as a single initial commit. It has no connection to the development history.
- The data pipeline, the balance simulator and most of the game tests need the generated game data. They do **not** run on this repository as it is (details below).

### The data pipeline without the content: what runs and what does not

`tools/gamedata/` holds two kinds of modules:

- **Framework (included)**: `core.py` (constants and formulas, the single source of truth for the numbers),
  `reg.py` (registry), `modifiers.py` and `modifier_names.py` (the catalogue of modifier keys), `tuning.py`,
  `export.py` (writes the JSON files).
- **Content (not included)**: the definitions of skills, items, equipment, monsters, zones, crates, economy, estate,
  quests, prestige, events, social and co-op rules, vocabulary and all the flavour text (`comedy_*.py`).

Consequences, stated plainly:

- `python tools/generate_data.py` **fails** (it imports the content modules). So does everything downstream that needs
  `data/`: `balance_sim.py`, `validate_data.py` (nothing to validate), `sync_data.py`, `make_placeholders.py`,
  `export_reference_values.py`, `make_appendices.py`, `make_schema_doc.py`, `check_all.py`.
- The Python tests `test_coherence.py`, `test_ui_keys.py` and `test_audio_levels.py` need data, assets or both.
- Almost all GUT tests need the data (see **Tests**).
- What does work: the formulas and their reference test, the registry/catalogue/tuning/export modules, the GDScript
  code itself (reading, linting, editing, refactoring), the UI strings, the docs, `make_audio.py` and `make_ui_frames.py`.

The maintainers may publish the content later. When they do, the exporter that produced this repository
(`--con-contenuto`) adds exactly the content modules and the tools that depend on them.


## Quick start (no Godot, no game data needed)

These two checks run on the repository exactly as published (Python 3.11+, standard library only) and are what the CI runs:

```
python tests/test_framework_standalone.py   # formulas vs reference values, small config/string files
python tools/gd_lint.py game                # syntax-level lint of every GDScript file
```

A good first contribution is anything that these checks cover: formula fixes, lint rules, documentation, localisation strings.

## Building and trying it

Requirements: **Godot 4.7.2** (standard edition, not .NET), **Python 3.11+**, Git.

1. Install the Python dependency: `pip install -r tools/requirements.txt`.
2. Point `GODOT_BIN` at the Godot executable (the *console* build on Windows), for example
   `export GODOT_BIN=/opt/godot/Godot_v4.7.2-stable_linux.x86_64` or, in PowerShell,
   `setx GODOT_BIN "C:\Godot\Godot_v4.7.2-stable_win64_console.exe"`.
3. Open the folder `game/` in the Godot editor (or run `godot --path game`). The first start imports the resources.
4. Without the game data the game cannot run: by reading the code, `DataRegistry` logs
   `cartella dati mancante: res://data` (data folder missing) and the screens that read data cannot work. The game needs
   a `game/data/` folder with the JSON tables described in `docs/18_schemi_dati.md`. (This was read from the code; the
   export was not tried in a Godot session.)

### Placeholders and your own data

- **Placeholder images:** `python tools/make_placeholders.py` draws a plain placeholder image for every image path
  that the data refers to, using the native sizes in `assets_plan/asset_specs.json` (needs the data and Pillow).
  Real art can be dropped into `game/assets/` later; existing files are never overwritten without `--force`.
- **Your own data:** the pipeline is `tools/generate_data.py` (writes `data/*.json` from the modules in `tools/gamedata/`)
  then `tools/validate_data.py` (schema and cross-reference checks), `tools/balance_sim.py` (balance targets)
  and `tools/sync_data.py` (copies the data into `game/data/`). `docs/18_schemi_dati.md` documents every table;
  `tools/gamedata/reg.py` is the registry the content modules fill in. Writing your own content modules,
  or your own JSON that follows the schemas, is how you obtain a running game from this repository.
- **Audio:** `python tools/make_audio.py` synthesises the sound set (additive synthesis, filtered noise, convolution reverb).

## Tests

There are two test suites.

**Python (`tests/`)**: `python tests/test_framework_standalone.py` runs on the repository as it is: it checks the
formula module `tools/gamedata/core.py` against `tests/reference_values.json` and the integrity of the small config and
string files. `tests/test_ui_keys.py` needs the generated data (it cross-checks UI keys against the quest data), and
`tests/test_audio_levels.py` needs the rendered audio: run `python tools/make_audio.py` first (about 90 seconds; needs numpy,
and `ffmpeg` in the PATH for Ogg Vorbis, otherwise it writes WAV; it passed in the export check).

**GUT (`game/tests/`, 177 files)**: run with `python tools/run_tests.py` (headless Godot; exit code 0 = green;
`--select NAME` filters by file name). Almost all of them boot the `DataRegistry` and the game systems and therefore
**need the game data**. By a static check of their source, these files do not reference the data, the autoloaded
game or the content fixtures, so they are the candidates that should run on this repository as it is:

- `test_number_cell_format.gd`
- `test_rng.gd`
- `test_snapshot_cache.gd`
- `test_virtual_grid.gd`

Run them with `python tools/run_tests.py --select test_rng.gd` (one at a time) after step 1-2 above. **This list comes
from reading the code; it has not been confirmed by a Godot run**, because the export was prepared on a machine
without Godot. Godot's autoloads load at start-up and report a missing data folder as an error, so treat a red result
on these files as a lead to investigate, not as proof of a bug.

For a syntax-level check that needs no Godot, `python tools/gd_lint.py game` checks bracket balance, string
termination and indentation of every GDScript file. It is deliberately simple and is not a replacement for
opening the project in Godot.

The CI workflow (`.github/workflows/ci.yml`) runs only what works without data: Python byte-compilation of `tools/` and
`tests/`, `tools/gd_lint.py`, and `tests/test_framework_standalone.py`. It uses no secrets.

## Project rules in short

1. **Generated data is never edited by hand**: change the content modules, regenerate, validate, simulate, sync.
2. **No balance numbers in GDScript.** Constants come from `data/constants.json`; formulas are ported 1:1 from
   `tools/gamedata/core.py` into `Formulas.gd` and checked against `tests/reference_values.json`.
3. **Logic is separate from UI.** Systems are pure, deterministic `RefCounted` classes in `game/src/systems/`, tested
   with GUT; the UI listens to `EventBus` and calls the systems.
4. **One modifier system**: every bonus goes through `Modifiers.gd` with the add/more rule.
5. **Ethical crates** (see below).
6. **Bilingual text**: `{"it","en"}` in data, `tr()` plus `localization/ui_strings.csv` in the UI; no hard-coded visible strings.
7. **Safe saves**: atomic writes, backups, schema version with migrations.
8. **Original names only**: no names, art or text taken from other games or brands.
9. **Stable prestige**: any bonus that speeds up its own layer is asymptotic, and every layer has a simulator check.

More in `CLAUDE.md` and `docs/17_architettura_godot.md` (the documents are written mostly in Italian).

## The crates are not gambling

The crate system follows `docs/09_casse_finiture.md` and `docs/24_legale_etica.md`. In short:

- Crates and keys are earned or crafted **with in-game currency only**. There is no real-money purchase, ever,
  and no way to buy in-game currency.
- No trading between players and no stakes mode (no upgraders, coin flips, crash games, jackpots or wagered battles).
- All drop probabilities are always visible. The result is drawn **before** the animation, and the filler items in the
  reel use their real probabilities.
- Cosmetic finishes may carry small permanent bonuses, which is stated plainly in the game text.

Any change that goes against these rules must be refused and flagged.
